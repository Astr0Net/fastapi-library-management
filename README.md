# سامانه مدیریت کتابخانه با FastAPI (fastapi-library-management)

این پروژه یک وب‌سرویس ساده و آموزشی برای مدیریت کتابخانه است که با استفاده از فریم‌ورک **FastAPI** و کتابخانه اعتبارسنجی **Pydantic** پیاده‌سازی شده است.

> **نکته بسیار مهم درباره ذخیره‌سازی داده‌ها:**
> در این پروژه از هیچ‌گونه پایگاه داده (Database)، ORM، فایل ذخیره‌سازی محلی یا سرویس خارجی استفاده نشده است. تمامی اطلاعات کتاب‌ها صرفاً در متغیرهای درون حافظه اصلی برنامه (RAM) نگهداری می‌شوند؛ بنابراین با هر بار راه‌اندازی مجدد یا توقف برنامه، تمامی داده‌ها از بین خواهند رفت (Data Loss) که رفتاری کاملاً طبیعی و مورد انتظار برای این پیاده‌سازی است.

## مدل داده کتاب (Book Data Model)

هر کتاب شامل سه فیلد زیر است:

- **`id`:** یک عدد صحیح مثبت (`integer > 0`) که به صورت خودکار توسط سرور با استفاده از شمارنده افزایشی تولید می‌شود. کلاینت‌ها مجاز به ارسال یا تغییر شناسه نیستند و با حذف یک کتاب، شناسه آن هرگز مجدداً استفاده نخواهد شد.
- **`title`:** عنوان کتاب؛ رشته الزامی و غیرخالی. هرگونه فاصله خالی (whitespace) در ابتدا و انتهای آن حذف می‌شود.
- **`author`:** نام نویسنده؛ رشته الزامی و غیرخالی. هرگونه فاصله خالی (whitespace) در ابتدا و انتهای آن حذف می‌شود.

## نقاط پایانی API (Endpoints)

| متد HTTP | مسیر (Path) | هدف و شرح عملکرد | کد وضعیت موفقیت |
| :--- | :--- | :--- | :--- |
| `GET` | `/books` | دریافت فهرست تمامی کتاب‌های موجود (در صورت عدم وجود کتاب، آرایه خالی `[]` برمی‌گرداند) | `200 OK` |
| `POST` | `/books` | ثبت کتاب جدید با تولید خودکار شناسه در سمت سرور | `201 Created` |
| `GET` | `/books/{id}` | دریافت اطلاعات یک کتاب مشخص بر اساس شناسه | `200 OK` |
| `PATCH` | `/books/{id}` | ویرایش جزئی عنوان، نویسنده یا هر دو (بدون تغییر شناسه و با حفظ فیلدهای ارسال‌نشده) | `200 OK` |
| `DELETE` | `/books/{id}` | حذف کتاب مشخص شده با شناسه | `204 No Content` |

## توالی و سناریوی کاربردی تست با دستورات cURL

نمونه‌های زیر در یک توالی منطقی و یکپارچه مرتب شده‌اند: ابتدا کتابی ایجاد می‌شود، سپس فهرست و مشخصات آن خوانده شده، ویرایش اعمال گردیده و در نهایت حذف می‌شود.

### ۱. ایجاد کتاب جدید (`POST /books`)

درخواست:
```bash
curl -X POST "http://127.0.0.1:8000/books" \
     -H "Content-Type: application/json" \
     -d '{"title": "Clean Code", "author": "Robert C. Martin"}'
```

پاسخ نمونه (`201 Created`):
```json
{
  "id": 1,
  "title": "Clean Code",
  "author": "Robert C. Martin"
}
```

### ۲. دریافت فهرست تمام کتاب‌ها (`GET /books`)

درخواست:
```bash
curl -X GET "http://127.0.0.1:8000/books"
```

پاسخ نمونه (`200 OK`):
```json
[
  {
    "id": 1,
    "title": "Clean Code",
    "author": "Robert C. Martin"
  }
]
```

### ۳. دریافت مشخصات یک کتاب با شناسه (`GET /books/{id}`)

درخواست:
```bash
curl -X GET "http://127.0.0.1:8000/books/1"
```

پاسخ نمونه (`200 OK`):
```json
{
  "id": 1,
  "title": "Clean Code",
  "author": "Robert C. Martin"
}
```

### ۴. ویرایش جزئی کتاب (`PATCH /books/{id}`)

می‌توان فیلد `title`، فیلد `author` یا هر دو را ویرایش کرد. در صورت ارسال بدنه خالی `{}`، عملیاتی صورت نگرفته و کتاب بدون تغییر بازگردانده می‌شود.

درخواست برای ویرایش عنوان:
```bash
curl -X PATCH "http://127.0.0.1:8000/books/1" \
     -H "Content-Type: application/json" \
     -d '{"title": "Clean Code: A Handbook of Agile Software Craftsmanship"}'
```

پاسخ نمونه (`200 OK`):
```json
{
  "id": 1,
  "title": "Clean Code: A Handbook of Agile Software Craftsmanship",
  "author": "Robert C. Martin"
}
```

### ۵. حذف کتاب (`DELETE /books/{id}`)

درخواست:
```bash
curl -X DELETE "http://127.0.0.1:8000/books/1"
```

پاسخ نمونه (`204 No Content`):
پاسخ این درخواست دارای کد وضعیت **204 No Content** بوده و فاقد هرگونه بدنه پاسخ (Empty Body) است.

## مدیریت خطاها

- **کد خطای `404 Not Found`:**
  در صورتی که کتابی با شناسه درخواستی در حافظه برنامه پیدا نشود (در متدهای `GET`، `PATCH` و `DELETE`)، این خطا همراه با پیامی شفاف مانند `"Book with ID 1 not found"` برگردانده می‌شود.

- **کد خطای `422 Unprocessable Entity`:**
  در صورتی که داده‌های ارسالی کلاینت با قوانین اعتبارسنجی تطابق نداشته باشند، این خطا بازگردانده می‌شود. مواردی که منجر به این خطا می‌شوند عبارتند از:
  - ارسال شناسه‌های نامعتبر در مسیر URL (مانند عدد صفر، اعداد منفی یا رشته‌های غیر عددی).
  - ارسال فیلدهای ناشناخته یا اضافه که در مدل تعریف نشده‌اند (از جمله ارسال `id` توسط کلاینت در متدهای `POST` یا `PATCH`).
  - ارسال رشته‌های خالی یا رشته‌هایی که صرفاً شامل کاراکترهای فاصله سفید (whitespace) هستند برای `title` یا `author`.
  - ارسال مقدار صریح `null` برای فیلدهای `title` یا `author`.
